# Ошибки и исправления

## 2026-11-21

### Запуск команд

Первый запуск PowerShell завершился ошибкой окружения `helper_sandbox_lock_failed`: отказано в изменении прав каталога `C:\Users\user\.codex\.sandbox-bin`.

Чтение файлов повторено через разрешённый запуск с `require_escalated`. Права и настройки песочницы не изменялись.

### Ссылка на документацию

Страница учебника scikit-learn `https://scikit-learn.org/stable/tutorial/text_analytics/working_with_text_data.html` вернула HTTP 404.

Вместо неё проверены официальные страницы `TfidfVectorizer` и `LogisticRegression`; рабочие ссылки включены в README.

### Инициализация Kafka KRaft

Официальный образ Kafka не форматировал хранилище только с `controller.quorum.bootstrap.servers`: требовал флаг выбора начальных контроллеров. Для одного брокера выбран статический `controller.quorum.voters=1@kafka:9093`, а идентификатор кластера заменён на корректный UUID. После исправления брокер и оба топика запущены, три потребителя аналитики получили по одной партиции.

### Scope и профили Keycloak

При импорте собственного client scope стандартные scopes автоматически не создавались. Добавлен `CreateDefaultClientScopes=true`. В default scopes клиентов включён `basic`, без которого отсутствовал `sub`; у сервисной учётной записи каталога добавлен `kc-admin-api`, необходимый для Admin API в Keycloak 26.8. Начальные профили дополнены email и фамилией, чтобы вход не останавливался на проверке профиля.

### CORS и документация API

Шлюз мог дублировать заголовок CORS от Keycloak. Заголовок upstream скрыт, разрешённый origin задаётся через WEB_URL. Для Swagger/OpenAPI настроены ROOT_PATH и маршруты шлюза; все три страницы документации и схемы доступны через собственные префиксы.

Браузерный клиент использовался только для проверки интерфейса. После проверки его код, Keycloak client и CORS-настройки удалены: итоговый продукт содержит только запрошенные мобильные платформы Android/iOS. Мобильный PKCE-вход отдельно проверен с окончательным redirect URI.

### Ошибки экспортёра логов

Повышение уровня логов OpenTelemetry до WARNING не предотвращало повторный экспорт ошибок самого экспортёра. На OTLP LoggingHandler добавлен фильтр внутренних логгеров; проверен неуспешный экспорт без рекурсивной отправки ошибок.

### Проверка HTTP-входа

HTTPX не отправлял Secure cookies по HTTP на localhost, в отличие от браузера. Временный интеграционный клиент приведён к поведению браузера только для localhost. Клиент продукта использует обычные cookies системного браузера; его код не менялся для этой проверки.

### Передача контекста Kafka

Аналитика первоначально выбирала контекст исходного HTTP-запроса из outbox раньше контекста producer span. Приоритет отдан Kafka-заголовкам; сохранённый контекст используется как резервный.

### Подготовка Android SDK

В окружении отсутствовали Flutter, Java и Android SDK. Инструменты установлены локально в игнорируемую папку `.tools`, без изменения системных переменных. Batch-обёртка Android command-line tools некорректно разбивала имена пакетов; требуемые SDK и NDK установлены через native Android CLI. После установки сборка `assembleDebug` завершилась успешно.
